# TODO 2026-09-07 — account/extensions Seite leer (brandis.eu)

## Symptom
`https://cloud.brandis.eu/account/extensions` rendert komplett leer
(nur `<div class="w-full lg:w-3/4 xl:w-1/2"><!----></div>`).
Keine Tabelle, kein "No extensions available", keine H1, keine Fehlermeldung.
Gleiche Seite auf `cloud.xwork.cloud/account/extensions` funktioniert normal.

## Ursache (gefunden)
Console-Error beim Rendern der Seite:
```
TypeError: F(...).filter is not a function
  at Proxy.flatMap
  at Proxy.getExtensionPoints
```
`accountExtensions.vue` ruft `extensionRegistry.getExtensionPoints()`.
Diese Methode macht `unref(extensionPoints).flatMap(e => unref(e).filter(...))`.

Im ExtensionRegistry-Store liegt in `extensionPoints` (Ref von Ref<EP[]>)
eine Gruppe (Index 4), deren `.value` **ein leeres Objekt `{}` statt ein Array** ist.
`unref(gruppe).filter` → `.filter is not a function` → Render-Error → Vue bricht
den ganzen Subtree ab → leere Seite.

Daten sind ansonsten korrekt vorhanden:
- folderviews EPs (aktenzeichen-display, app-compact, app-new-window) sind
  registriert, mit userPreference + passenden enabled/disabled Extensions.
- Filter-Logik selbst würde 4 Zeilen liefern (3 folderviews + 1 progress-bar).

Der Bug ist **nicht** in opencloud_folderviews. Er liegt im Web-Core:
eine Extension/App registriert einen leeren (nicht-Array) extensionPoints-Ref
über `registerExtensionPoints`. Gruppen-Layout im Store:
```
0: web-app-files (22 EPs)
1: web-app-search (app.search.provider)
2: web-app-admin-settings (5 EPs)
3: web-app-preview (app.preview.toolbar-actions)
4: *** LEERES OBJEKT {} ***   <- kaputt
5: folderviews (4 EPs)
6: account-layout (app.files.navItems)
7: admin-settings navItems (app.admin-settings.navItems)
8: web-runtime core (8 EPs)
```

## Schuldige App (GEFUNDEN)
**noetron-transkript / Recorder** — `noetron-transkript/apps/recorder/src/index.ts:94`
lieferte `extensionPoints: computed(() => ({}))` (leeres Objekt statt Array).
Web-Core (classic.ts:114) gibt das 1:1 an `registerExtensionPoints` weiter →
kaputte Store-Gruppe → `getExtensionPoints()` wirft → leere Seite.

## Fix (erledigt)
- [x] **Recorder**: `extensionPoints`-Feld aus `apps/recorder/src/index.ts`
      entfernt (App hat keine EPs, nur extensions). `computed`-Import bleibt
      (wird für isPersonalSpace + extensions genutzt).
- [x] **Web-Core defensiv**: `extensionRegistry.ts` — `getExtensionPoints()`
      und `unregisterExtensionPoints()` normieren `unref(e)` per
      `Array.isArray(...) ? unref(e) : []`, damit eine kaputte App nie wieder
      die gesamte Settings-Seite downbringt.
